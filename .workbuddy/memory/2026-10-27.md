## 修复"投递文件无法触发接口应用"问题
- 根因：`looper.py` 只启动了 SentryWatcher，未创建事件队列消费者，PluginRunner/ClerkArchiver 管道未接线；事件入队后无人处理。
- 重写 `looper.py`：每个监控目录创建 EventBufferQueue + concurrency 个工作线程，消费事件 → 依次执行 strategies（PluginRunner 子进程）→ 成功 archive_success / 失败 dump_panic_report + archive_error。
- `plugin_runner.py`：run() 新增 params（argv[2] JSON + TRIGGERFORGE_PARAMS 环境变量）与 python_path（隔离虚拟环境）支持；结果附带 stdout/stderr/exit_code。
- `schema.py`：plugin_version 改为可选；新增顶层 plugin_directory 与 debounce_seconds 字段。
- `watcher.py`：未传 dispatch_queue 时回退内部队列，避免事件静默丢失；支持从 watch_configs 读取 debounce_seconds。
- `config.yaml`：旧格式（watch_path/plugins 列表）无法通过 Schema 校验，改写为 watch_folders 生产格式。
- 验证：28 个测试全部通过；端到端冒烟（投递文件→插件执行→归档 success_folder）通过。
- 测试环境：隔离 venv `C:/Users/zyb/.workbuddy/binaries/python/envs/default`，需 `pip install -e . --no-build-isolation`。
